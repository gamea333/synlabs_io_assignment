P2 — LLM-as-Judge pipeline: suite in → structured verdicts → report / A-B decision

flowchart TB
  S[Test suite JSON / YAML
id, input, system_prompt, model_output?,
expected_output?, criteria?, context?] --> L[load_suite: schema + duplicate-id check]
  L --> G{model_output present?}
  G -- no --> GEN[Generator config A or B
GENERATOR_* env: qwen3.8-27b
prompt v1 / prompt v2]
  G -- yes --> P
  GEN --> P[Judging-prompt construction
v1: anchored 6-criterion rubric + calibration examples
+ evidence-quote rule + 'length is not quality'
+ 'confidence is not evidence' + code-computed counts]
  P --> PW[Pointwise
per-criterion 1-5]
  P --> SWAP[POSITION-BIAS MITIGATION
pairwise run twice: A,B then B,A
map 2nd verdict back to config labels]
  PW --> J[Judge model call
JUDGE_* env: gpt-oss-120b
JSON mode, temperature 0]
  SWAP --> J
  J --> LOG[(logs/calls.jsonl
full prompt + raw response + tokens
audit log AND replay cache)]
  J --> PARSE[VERDICT PARSE LADDER
strict json → extract outer object → repair
→ retry once → regex fallback → 'failed' counted]
  PARSE --> VAL[Schema validation
clamp + flag out-of-range, missing criteria]
  VAL --> CASE[Per-case aggregation
weighted score, pass = >=3.5 and floors
pairwise final = agree ? verdict : tie]
  CASE --> REP[Suite report
pass rate, mean + per-criterion scores,
win rate, flip rate, parse stats, judge calls/tokens]
  REP --> DEC[A/B decision
sign test + bootstrap CI, rule fixed in advance]
